# Chest X-ray Training Companion

Educational tool for medical students and educators to practise chest X-ray
interpretation with structured AI-generated feedback. Phase 1 uses
**MedGemma 1.5-4B-IT** (Google's medical vision-language model) over a
**curated subset of NIH ChestX-ray8** (30-60 cases, 6 findings). The system
is split into a FastAPI backend and a React/TypeScript SPA, with Clean
Architecture on the backend and a thin component-based UI on the frontend.

> Educational use only. Outputs are generated by a non-clinical AI model
> and must not be used for diagnosis or patient care. Always consult a
> qualified radiologist.

## Current state (MedGemma inference live)

We are at the **end of Step 6, plus the real MedGemma path**. Inference now
runs end-to-end against `google/medgemma-1.5-4b-it` in the Kaggle notebook:
case images travel to the tunnel as base64 bytes, the model's JSON is
statically repaired (fences, prose, trailing commas, truncation) and
re-prompted once if that fails, and the model's differentials and key
observations reach the UI. See `docs/plans/2026-09-05-medgemma-support.md`. The backend boots, the
manifest is queryable, students can register/login, submit attempts,
and get structured `Feedback`. Educators and admins (invited by an
existing admin) can browse the review queue, fetch attempts, and submit
rubric-based reviews. `python scripts\run_eval.py` runs the Phase 1
metrics (structure validity, finding recognition, per-finding
breakdown, latency, token usage) and writes a JSON + Markdown report.

**The 50% development milestone is now complete.** This was the
supervisor review requirement before thesis submission.

## Try Step 5 + 6 today

1. **Terminal 1 — backend:**
   ```powershell
   cd backend
   python scripts\dev.py install-dev                                # create .venv, install deps, pip install -e .
   python scripts\dev.py real-data                                   # build the 300-case real-data manifest
   python scripts\dev.py seed                                       # create the first admin (idempotent)
   python scripts\dev.py run                                        # uvicorn on http://127.0.0.1:8000
   ```
   > **`real-data` is the one command to remember.** It wipes any
   > existing `data/raw` + `data/processed`, then runs
   > `download_nih_subset --source local` + `build_manifest` against
   > the bundled `..\Dataset\images\` + `..\Dataset\Data_Entry_2017_v2020.csv`.
   > If you unzipped the NIH box download to a different location,
   > pass `--local-dir <path> --metadata-csv <path>`. The yield is
   > **300 cases** at the default `n=50` (5 findings × 50 + 50
   > negatives; *fracture* is dropped because the NIH 14 NLP-mined
   > labels don't include it). Override with `--n-per-finding` for
   > larger eval sets. If you ever see the API toast
   > *"No curated case manifest found. From the backend folder run:
   > python scripts\dev.py real-data"*, just run that command.
2. **Terminal 2 — frontend:**
   ```powershell
   cd frontend
   npm install
   npm run dev                            # http://127.0.0.1:5173
   ```
3. Open `http://127.0.0.1:5173/register`, create a student account.
4. Open a case (`/cases/<id>`), type a free-text interpretation, click
   **Submit** — structured feedback (likely finding, key signs, teaching
   point) appears. Each case card in the grid shows a thumbnail plus
   `Case of {Label}` and a demographics line
   (`56-year-old male · AP view`).
5. To exercise the review flow: stop the backend, run
   `python scripts\dev.py seed --seed-educator` (or sign in as the seeded
   admin and invite an educator via the API), then log in as that educator
   to see `/reviews`.
6. **Run the eval harness:**
   ```powershell
   python scripts\dev.py eval --max-cases 30                            # dry-run
   python scripts\dev.py eval --runtime kaggle_tunnel --max-cases 30    # real model
   # → reports/phase1_eval.json + reports/phase1_eval.md
   ```
7. **Real MedGemma:** launch the Kaggle notebook, paste its ngrok URL into
   `backend/.env` as `MEDGEMMA_TUNNEL_URL`, set
   `MEDGEMMA_RUNTIME=kaggle_tunnel`, and **restart the backend** (settings
   are cached per process). Full instructions in `docs/KAGGLE_RUNTIME.md`.
   Verify with `curl http://127.0.0.1:8000/api/v1/healthz` — it pings the
   tunnel, so a stale URL reports `"status": "degraded"`.

## Prerequisites

- **Python 3.11+** (tested on 3.13).
- **Node 22+** and **npm 11+** for the frontend.
- A terminal that can run `python` (Windows: use the `py` launcher or
  any python on PATH).

You do **not** need `make`. The backend ships with `scripts/dev.py` for
Windows-friendly dev commands. The frontend uses plain `npm` scripts.

## 1. Backend

```powershell
cd backend
python scripts\dev.py install-dev                                # create .venv, install deps, pip install -e .
python scripts\dev.py real-data                                   # build the 300-case real-data manifest
python scripts\dev.py seed                                       # seed the first admin
python scripts\dev.py run                                        # uvicorn on http://127.0.0.1:8000
```

> `real-data` is the one command to remember for the real-data
> workflow. It auto-detects `..\Dataset\images` +
> `..\Dataset\Data_Entry_2017_v2020.csv` and accepts `--local-dir`,
> `--metadata-csv`, and `--n-per-finding` overrides. The lower-level
> `data --source {stub,local}` target still works for fine-grained

(override with `--email` / `--password` or `ADMIN_EMAIL` / `ADMIN_PASSWORD`

educator.

## 2. Frontend

In a second terminal:

```powershell
cd frontend
npm install                            # one-time
npm run dev                            # http://127.0.0.1:5173
```

**Use `127.0.0.1`, not `localhost`.** On Windows `localhost` resolves to
IPv6 first and Vite's default `localhost` binding can refuse the IPv4
request. The repo pins the dev server to `127.0.0.1` in `vite.config.ts`
to avoid this.

Vite proxies `/api` to `http://127.0.0.1:8000`, so the SPA talks to the
backend on the same origin in dev.

Other scripts:
```powershell
npm run build                          # tsc -b + vite build (production bundle)
npm run preview                        # serve the production build locally
npm run lint                           # oxlint
```

### What you can do today

- **Register a student** at `http://127.0.0.1:5173/register` (open
  self-registration).
- **Browse the case list** at `http://127.0.0.1:5173/cases` — 4-column
  grid of CXR thumbnails with `Case of {Label}` titles and a
  demographics sub-line (`56-year-old male · AP view`). Size is
  determined by `--n-per-finding` passed to the `data` target; with
  the NIH subset and `n=50` you get **300 cases** (5 findings × 50 +
  50 negatives), balanced across `train / val / test` (70/15/15).
- **Submit an attempt** at `http://127.0.0.1:5173/cases/{id}` — CXR viewer
  + free-text form; submission returns structured feedback (likely
  finding, key signs, teaching point) via the dry-run analyzer (default)
  or the real MedGemma via the Kaggle tunnel (see `docs/KAGGLE_RUNTIME.md`).
- **Review queue** at `http://127.0.0.1:5173/reviews` (educator/admin
  only) — list of attempts, open one to score against the rubric.
- **Educator invite** is an admin-only API call (no UI yet):
  `POST /api/v1/auth/register` with `{role: "EDUCATOR", inviteAdminId: "<admin-id>"}`.

### Try the toast explicitly

1. Start only the frontend (`npm run dev`); leave the backend stopped.
2. Open `http://127.0.0.1:5173/register`.
3. Fill in any email/password and submit.
4. A red toast appears bottom-right: **"Cannot reach the server"** with
   detail "The backend is unreachable. Is the API server running on
   http://127.0.0.1:8000?" and a hint to run
   `python scripts\dev.py run`.
5. Start the backend, submit again — the request succeeds and you are
   redirected to `/cases`.
