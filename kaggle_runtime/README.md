# Kaggle runtime

The Kaggle notebook hosts a small FastAPI app that loads
`google/medgemma-1.5-4b-it` and exposes a `POST /generate`
endpoint over a public ngrok tunnel. The backend calls that tunnel
through the `KaggleTunnelMedGemmaClient`.

Images arrive as base64 bytes in the request body. The backend's case URLs
(`/images/00000013_023.png`) resolve against its own static mount and mean
nothing inside this container, so a reference would not work — see
`docs/KAGGLE_RUNTIME.md` for the full contract.

## 1. One-time Kaggle setup

Create a new Kaggle notebook with **GPU T4 x2** (free tier) or
**GPU P100** (better), and add this as the first cell:

```python
%pip install -q \
    fastapi==0.115.0 \
    uvicorn[standard]==0.32.0 \
    pydantic==2.9.2 \
    pyngrok==7.2.0 \
    transformers==4.46.0 \
    accelerate==1.0.0 \
    bitsandbytes==0.44.0 \
    pillow==10.4.0

!git clone https://github.com/<this repo>.git /kaggle/cxt
%cd /kaggle/cxt
```

Kaggle secrets — add a secret named `NGROK_AUTHTOKEN` (from
<https://dashboard.ngrok.com/get-started/your-authtoken>) in the notebook
editor under **Add-ons → Secrets**.

## 2. Start the server

```python
import os
from kaggle_runtime.medgemma_server import start_in_background

os.environ["MEDGEMMA_MODEL"] = "google/medgemma-1.5-4b-it"
os.environ["MEDGEMMA_PRECISION"] = "bf16"   # "bf16" | "fp32" | "8bit" | "4bit"
os.environ["NGROK_AUTHTOKEN"] = "<your token>"  # or pull from Kaggle Secrets

# Loads the checkpoint first, then opens the tunnel, so the URL is only
# printed once the model can actually serve. Expect several minutes.
ngrok_url = start_in_background(port=8000)
print("MEDGEMMA_TUNNEL_URL =", ngrok_url)
```

The cell prints the public HTTPS URL. Copy it. Keep the cell alive (e.g.
`time.sleep(...)`) so the server stays up.

`%cd /kaggle/cxt`, not `/kaggle/cxt/kaggle_runtime` — the import above is a
package import and fails from inside the package directory.

## 3. Backend configuration

In the backend `.env` (copy from `backend/.env.example`):

```dotenv
MEDGEMMA_RUNTIME=kaggle_tunnel
MEDGEMMA_TUNNEL_URL=https://<the-url-above>.ngrok-free.app
MEDGEMMA_MODEL=google/medgemma-1.5-4b-it
MAX_EVAL_CASES=30
```

Restart the backend after editing `.env` — settings are cached per process.

For local development without Kaggle, set `MEDGEMMA_RUNTIME=dry_run` and leave
`MEDGEMMA_TUNNEL_URL` blank; the backend uses a deterministic
`DryRunMedGemmaAnalyzer` that doesn't touch the network.

> There is no `MEDGEMMA_DRY_RUN` setting. `MEDGEMMA_RUNTIME` is the only
> switch; anything else is ignored.

## 4. Verify

```bash
# In a separate shell on your machine
cd backend
python scripts/dev.py real-data
python scripts/dev.py run

# Reports the runtime and actually pings the tunnel.
curl http://127.0.0.1:8000/api/v1/healthz
```

`"status": "degraded"` with `"tunnelReachable": false` means the URL in `.env`
is stale — restarting the notebook issues a new one.

In the browser, open `http://127.0.0.1:5173/cases/<id>`, write an
interpretation, and submit. The request is forwarded to the Kaggle
tunnel, the model returns JSON, the backend parses it into a
`Feedback` entity, and the UI displays the structured feedback.

## Privacy

The notebook only ever sees:

- The image bytes of a de-identified public NIH ChestX-ray8 film.
- The clinical context (age, sex, view) already published with that dataset.
- The student's free-text interpretation.

It never sees student names, emails, or any other PII. The bytes go to a
temporary file for the pipeline to read and are deleted immediately after; they
are never logged and never persisted. The server logs only the payload size,
MIME type and prompt lengths. The student is identified only by a UUID
generated by the backend.
